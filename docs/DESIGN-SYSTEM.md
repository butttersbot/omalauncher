# Soma design system

Generated by `tools/design-system/build.py` from the **active look's** pack. Soma has switchable looks (theme
packs in `app/src/main/assets/packs/`); this file, `design/soma/soma.css`, `design/soma/template.html` and
`design/soma/design-system.html` describe whichever is picked. Generated now from **Manga**
(`manga`). When Boss picks another look, rerun `python3 tools/design-system/build.py` (it asks the phone which
look is active) and re-look any mockup you're still working on. Don't edit the generated files by hand.

## How it works: roles, mapped to the active pack

Mockups use **roles** (classes and CSS variables), never raw colours or font names. The generator fills each role
from the pack:

| Role | CSS | From the pack |
|---|---|---|
| Page | `--background`, `--foreground` | `[palette] background / foreground` |
| Card / panel | `.panel`, `--panel-fill`, `--panel-line`, `--hair`, `--radius`, `--shadow` | `[scrap] fill, border_color, border`, `[shape] radius`, `[scrap.shadow]` |
| Emphasised card | `.panel.ink`, `--alt-fill`, `--alt-ink` | `[scrap.alt]`, `[palette] alt / on_alt` |
| Title | `h1`, `h2`, `.display` | `[type.display]` |
| Body | `body`, `p`, `--body-size` | `[type.body]`, `[type.size] body` |
| Label / caption | `.caption`, `.label` | `[type.mono]` (weight, case, tracking) |
| Aside | `.hand` | `[type.hand]` |
| Chip / tab | `.tabs > .tab`, `.on` for the one showing | `[type.mono]`, palette ink |
| List row | `.rows > .row` | `--hair`, palette |
| Form field | `.field` | `--hair`, `--radius` |
| Option button | `.options > .option`, `.on` chosen | `--hair`, `--radius`, palette |
| Primary action | `.action` → `[ Label ]` in the accent | `[palette] accent` |
| Secondary action | `.action.secondary` → `[ Label ]` in ink | `[palette] foreground` |
| Badge | `.badge` | `[palette] spot` (or accent) |
| Focus | `:focus-visible` | `[scrap] focus_color, focus_width` |

Actions are Soma's bracketed words in every look (`[ Approve ]`, one line, never wrapped, at least 44 px tall).

## The active look: Manga

Manga, after features/manga-look/manga-mockup.html: every home page is a manga page, fixed panels in hairline ink on white paper, one spot red, and screentone where City Pop would use a color. Dragging one panel onto another trades what is in them; the lines never move. Read from real pages (Kimagure Orange Road, 1984; Inio Asano): borders are hairlines, the gaps between rows are wider than those between panels side by side, and the page keeps a deeper margin at the foot than at the head, as a printed volume does. Nothing casts a shadow; depth is the ink's and the tone's. What it leaves out is Console's (assets/packs/console/pack.toml). Its fonts are copied from the other looks, in fonts/ (SIL Open Font License): Dela Gothic One from Riso, Patrick Hand from Bujo, Schibsted Grotesk and JetBrains Mono; each voice also names the nearest system family as a fallback.

## Artifact question replies

Generated HTML opts in with `<meta name="soma-reply-to" content="phone:B">` in its head.
Use one fixed `phone:A`, `phone:B`, `phone:C`, or the exact known `mac:` thread key.
The declared recipient is untrusted until Boss reviews it. An artifact must never
choose a different recipient from JavaScript or claim that answers were delivered.

The template's Submit calls `soma.answer(text)` on an owner tap. Soma must show a
native review naming that fixed recipient and the complete text. Only Boss's
separate Send tap may deliver a normal message to that known thread/builder. Cancel
sends nothing. A plain browser/offline preview has no bridge and explains that.
Generated HTML gets no file/content access, credentials or general native API;
live web URLs cannot opt into this bridge. Subframes and non-gesture requests are
refused. Text is nonblank, limited to 4096 characters, with control characters
refused. Missing/duplicate declarations fail closed. Unknown recipients must be
rejected in native review, never rerouted to another agent. Version changes cancel
an open review. A native review is consumed once, not automatically retried.

Native AskUserQuestion forms use their nonce-bound approval answers instead;
they do not send a second chat message through the artifact bridge.

## Artifact mockup approval

Declare one `soma-canvas-cards` meta in the head. Its JSON content is exactly
`{"app":"hunch","cards":["hunch-today","hunch-market"],"version":"v6"}`.
Also declare `soma-reply-to` for the author. `soma.approve({app,cards,version,note?})`
requests native review only, on a main-frame owner gesture. The payload must match
the static declaration exactly; scripts cannot add cards or change the version.

The review names the app, version and every screen with Approve / Request changes.
Only Boss's separate native Approve tap authorizes Canvas. Native code resolves the
cards and checks the exact proposed assets/version before using the owner sign-in;
no owner key or Canvas API is exposed to HTML. Stale/missing cards fail closed.
Request changes reviews and relays Boss's note to the fixed author using the reply
path. Closing review does nothing. Cancel review on artifact version changes;
consume a confirmation once and never retry an uncertain approval automatically.
Show partial failures accurately and notify the author only of confirmed results.
The bridge foundation alone does not implement native review or Canvas submission.

|---|---|---|---|
| Cover | 1248 × 1972 | 475 × 751 | full screen |
| Unfolded | 2448 × 1848 | 932 × 704 | the side panel beside the chat, ≈466 × 704 |

Design for both; the side panel is the narrowest real width a mockup gets unfolded, and the cover is the tallest.

## Do and don't

- Do start from `design/soma/template.html` and use only the roles above; let text wrap and size by content.
- Do keep everything in one offline file: `soma.css` inlined, no CDN, no web fonts, no network calls.
- Do look before sending: `soma-look FILE` renders it at cover, unfolded and side-panel sizes, prints the PNGs and
  warns on overlapping or clipped text, horizontal overflow, empty (zero-height) content, network references, and a
  file made for a different look than the active one. `soma-canvas propose` refuses a file that hasn't been looked at.
- Don't hard-code colours or font names, use fixed heights that can come out zero, scale-to-fit
  (`transform: scale` from a measured height), or hover-only controls.
